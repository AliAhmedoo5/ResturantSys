# Independent customer money evidence

New Cashier checkouts write one immutable receipt event for each collected manual tender in the same SQLite transaction as its Order and stock effects. COD placeholders are not receipts. Amounts are signed Integer Paisa net of retained change; change and Cash Rounding remain separately visible. A refund links its negative tender and optional drawer PAY_OUT to one event. Stable command identities make independent receipt/refund retries return the existing result, rejecting conflicting retry payloads.

Cashiers use **Orders → Record receipt** to accept a partial Collection Due receipt in their current open Shift; the receiving Business Day and Shift are recorded independently from the originating Order. Settled Trip Locks prohibit direct further collections. Managers cannot execute these commands. The existing Cashier checkout and explicit refund interfaces write the same evidence automatically. Receipt and refund entries offer an optional late actual timestamp in Pakistan time; blank defaults to entry time.

Actual event time defaults to entry time. The domain receipt/refund contract also accepts an explicit late actual timestamp within the receiving open Shift and Business Day, never after recording time. Recording time is permanently stored in UTC. This is not a closed-day correction workflow. Any failed event validation rolls back all linked writes.

Partial cash receipts use whole rupees. The final cash balance rounds half-up to whole rupees using the existing Paisa Engine: 12.50 accepts 13.00 with +50 paisa variance; 12.49 accepts 12.00 with −49 paisa variance. A positive balance below 50 paisa can be finalized with zero cash. Digital receipts remain exact. The final receipt retains its rounding delta and a linked Order/receiving Shift variance ledger entry atomically; retries retain one entry. Original Order value and assignment remain unchanged.

Manager Cash and shifts contributing rows expose receipt/refund kind, signed amount, method, source, actual and recording timestamps, original and receiving relationships, actors, tender/movement links, change and rounding. Shared CSV/XLSX/PDF exports use those same snapshot columns. Business Day mode selects receiving assignments; calendar mode selects actual timestamps in Asia/Karachi. Cashier means Shift owner for these rows. Domain-only filters do not redefine whole-drawer metrics.

Schema 22 adds an empty append-only event ledger without backfilling historical tenders. Historical receiving attribution and timing remain unknown; original balances and sealed reports are preserved. Drawer calculation and new sealed reports use receiving evidence for linked tenders; unlinked historical tenders retain disclosed cohort semantics. Never sum an event with its own linked tender or Cash Movement as another financial effect.
